# שיבוץ צוות מטבח

אפליקציה בעברית (ממשק RTL) לשיבוץ צוות מטבח למשמרות. כל יום מזינים דוח נוכחות, והמערכת מייצרת שיבוץ ל-24 שעות קדימה (06:00–06:00). היא זוכרת את כל השיבוצים הקודמים, שומרת על כללי מנוחה קשיחים, מחלקת את העבודה בהוגנות ומתמודדת עם חוסר או עודף באנשים.

## הפעלה

נדרש Node.js 22.13 ומעלה. אין תלויות חיצוניות: המסד הוא SQLite המובנה ב-Node.

```bash
npm run seed      # טעינת נתוני דמה: 30 עובדים ומצב פתיחה (מחר בבוקר)
npm start         # http://localhost:3000
npm test          # בדיקות המנוע והשירות
npm run demo      # שלושת התרחישים → docs/totzaot-demo.md
```

המסד נשמר ב-`data/shibutz.db`. אפשר לשנות את המיקום עם `DB_PATH` ואת הפורט עם `PORT`.

## מסכים

| מסך | מה עושים בו |
|---|---|
| דוח נוכחות | מסמנים מי נמצא ומי בחופש: תיבות סימון, או הדבקה של רשימת שמות. מוצג "נדרש מול קיים" לפי משימה ותפקיד ולכל צוות. |
| לוח שיבוץ | שתי תצוגות: ציר זמן (שעות × משימות) ותצוגה לפי עובד. גרירה מחליפה בין אנשים. גרירה מרשימת "ללא שיבוץ" משבצת, וגרירה אליה מפנה עמדה. לחיצה על שיבוץ מציגה למה האדם נבחר, אילו חלופות נבדקו ומי נפסל ולמה. משם אפשר גם להחליף או לנעול. אחרי כל שינוי המערכת בודקת מחדש ומציגה הפרות ואזהרות. יש כאן גם "שבץ מחדש משעה X", פרסום, ייצוא לוואטסאפ ותצוגת הדפסה. |
| עובדים | הוספה ועריכה: שם/כינוי, תפקיד בסיס, תגיות, סטטוס, תאריך חזרה צפוי, הערות, צוות ומאגר פס קר. |
| היסטוריה | כל משמרת שפורסמה: עובד, משימה, עמדה, התחלה, סיום. אפשר לסנן לפי תאריכים ועובד. |
| הוגנות | שעות עבודה ב-7 וב-14 הימים האחרונים, משמרות לילה, משמרות פס קר, ומספר המנוחות המורחבות ומתי הייתה האחרונה. |
| מצב פתיחה | מסך חד-פעמי: מי בכל צוות, איפה כל צוות נמצא כרגע במחזור, ומי במאגר פס קר. מנהלנים מזוהים לפי תפקיד הבסיס. |
| הגדרות | כל השעות, גודלי ההרכבים, מינימום המנוחה, סדר הוויתור, החריגות והטיפול בעודף. אפשר לשנות הכול בלי לשנות קוד. |

## תהליך יומי

1. בסביבות 12:00 מגיע דוח הנוכחות, והמשתמש מסמן במסך "דוח נוכחות" מי נמצא ומי בחופש.
2. "שמור דוח וצור טיוטת שיבוץ" מייצר טיוטה ליממה הבאה. אם ביתרת היממה הנוכחית משובץ מישהו שסומן "בחופש", מוצגת הודעה עם קישור לשיבוץ מחדש.
3. עריכה ידנית: גרירה, החלפה ונעילה. שיבוץ נעול נשמר גם ביצירה מחדש.
4. פרסום: השיבוץ נשמר להיסטוריה. כשיש הפרה או חוסר בפס חם / הכנות, צריך לסמן אישור ידני.
5. שינוי באמצע היום: "שבץ מחדש משעה X" שומר את כל מה שנעול ואת מה שכבר התחיל לפני X, ומשבץ מחדש את השאר.

## האלגוריתם

הקוד ב-`src/manoa/`. הוא דטרמיניסטי: אותו קלט נותן תמיד אותו שיבוץ, ובשוויון מכריע מספר העובד.

**סדר השיבוץ**

1. **פס חם.** הצוות שתורו לפי המחזור משובץ לפי סדר החברים: השף לפס חם א, שני טבחים לפס חם א ושלושה לפס חם ב. חוסר מושלם בסדר הזה: חבר הצוות, אחר כך מי שללא צוות (עודף), ואחר כך מאגר פס קר. בחירום ממלאים קודם במחזור 8/8, ומאגר פס קר נשמר לפס קר.
2. **הכנות.** השף ו-3 טבחים מהצוות שתורו. מנוחה מורחבת ניתנת למי שקיבל הכי מעט מנוחות מורחבות לאחרונה. בשוויון היא ניתנת למי שעבד הכי הרבה בהכנות לאחרונה, ושאר הטבחים עובדים.
3. **פס קר.** חיפוש מוגבל על כל 8 המשמרות של היממה. קודם הוא ממקסם את מספר המשמרות המאוישות, ואחר כך מצמצם את הפגיעה במנוחה הארוכה (כלל רך 1). מאגר פס קר ומי שללא צוות קודמים לטבחים שסיימו מנוחה של 8 שעות. בשוויון קובע מי שעשה הכי מעט משמרות פס קר.
4. **מנהל.** קודם משובצות משמרות הלילה, למי שעשה הכי מעט לילות. אחר כך שאר המשמרות, לפי הכי מעט שעות עבודה.
5. **אופטימיזציה.** עודף: מי שנשאר בלי שיבוץ מחליף ליממה אדם מצוות, וזה מקבל "יום מנוחה מלא" ברוטציה. כיסוי תגיות: החלפת יממה בין שני טבחים כשזה משפר את כיסוי התגיות הרצויות בפס חם ולא מפר אף כלל.

**כללים קשיחים** (`kshichim.js`). כל מועמד נבדק מול ההיסטוריה, מול הטיוטה ומול המשמרות הקרובות של מחר לפי המחזור, כדי ששיבוץ של היום לא ישבור את מחר:

- מנוחה מינימלית אחרי פס חם, הכנות, פס קר (9 במצב מועדף, 6 במצב מינימום) ומנהל.
- אדם לא משובץ לשתי משימות חופפות.
- רק מי שמסומן "נמצא" משובץ.
- התאמה לתפקיד: שף אחד בדיוק בפס חם, ותמיד בפס חם א. מנהלן משובץ רק למשימת "מנהל".
- חריגה מותרת: המנוחה שלפני פס חם בוקר מסתיימת בהכנת שחר. לכן היא נמדדת עד 06:00, אף שהעבודה מתחילה ב-04:45.

**סדר הוויתור במקרה של חוסר.** המנוע מנסה קודם בלי ויתורים. אם נשארות עמדות לא מאוישות, הוא מפעיל את הצעד הבא שיכול לעזור ובונה מחדש:

1. מוציאים את הטבח ממשמרת מנהל 00–06.
2. פס קר עובר ל-3/6. אם עדיין חסר, משבצים אליו אנשים שסיימו מנוחה של 8 שעות.
3. חירום: מחזור 8/8 לפס חם, והכנות מאוישת מאנשים אחרים.

המצב (רגיל / חוסר / חירום) מוצג עם הסיבות. פס חם (6) והכנות (4) לא יורדים לעולם. אם אי אפשר לאייש אותן, מוצגת התראה בולטת עם פירוט מה חסר, והפרסום דורש אישור ידני.

**אזהרות** (`bdika.js`). כל כלל רך שלא התקיים מופיע כאזהרה, למשל: תגית חסרה בפס חם, מחליף בצוות, טבח שעבר לפס קר במקום מנוחה ארוכה, מנוחה של 3/6 אחרי פס קר, או מחזור 8/8.

## הנחות (ניתנות לשינוי בהגדרות)

- **מנוחה אחרי מנהל: 6 שעות.** האפיון לא קבע ערך.
- **מנוחה מורחבת:** הפסקה של 16 שעות לפחות בין משמרות, בלי ימי חופש באמצע. זו גם מנוחה שעדיין נמשכת.
- **משמרת לילה:** משמרת שמתחילה בין 22:00 ל-06:00.
- **מחזור 8/8:** שתי משמרות פס חם עם פחות מ-16 שעות ביניהן.
- **שף יכול לשמש גם כטבח** (מופעל כברירת מחדל): שף יכול להיות משובץ לעמדות טבח, לפס קר ולטבח במנהל, אבל טבח קודם לשף באותה שכבת עדיפות. עמדת השף לא משתנה: שף אחד בדיוק בפס חם, ותמיד בפס חם א.
- **"נדרש מול קיים":** מחושב לפי 4 צוותים (המצב המלא).
- **עודף:** האנשים הנוספים ממלאים קודם חוסרים, אחר כך פס קר, וכך משחררים טבחים מהצוותים למנוחה מורחבת. מי שנשאר בלי שיבוץ מחליף אדם מצוות ליממה (יום מנוחה מלא). אפשרות אחרת: להקים צוות חמישי במסך מצב פתיחה, והמחזור מתארך אוטומטית.
